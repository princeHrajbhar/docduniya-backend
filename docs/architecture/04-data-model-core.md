# Core collection data dictionary

This is a logical Mongoose/BSON specification, not executable schemas. Collections describe the full marketplace and outpatient target; optional communication, insurance, hospital and monetization features are enabled by release scope. Do not create empty collections just to match a diagram.

## Notation and universal rules

`id` = BSON ObjectId; `s` = bounded Unicode string; `i` = integer Number restricted to the safe integer range; `d` = Decimal128; `b` = Boolean; `t` = UTC BSON Date; `date` = validated date-only string; `E(a,b)` = string enum; `ref(collection)` = ObjectId reference. `?` means optional, otherwise required at the stated lifecycle stage. `[T]n` means a bounded array of at most n values. All unspecified optional fields are absent, not null. Conditional requiredness is enforced by command DTO, domain policy and schema validation.

Every mutable aggregate has `B`: `_id:id`, `createdAt:t`, `updatedAt:t`, `createdBy:Actor`, `updatedBy:Actor`, `version:i=0`, `schemaVersion:i=1`. Append-only records use `A`: `_id`, `createdAt`, `createdBy`, `schemaVersion`, without misleading mutable timestamps/version. `Actor={kind:E(USER,SERVICE),id:s}`; user actor IDs resolve to `users` and service IDs to an allowlisted service identity. No arbitrary user-supplied actor values.

Scope `G` means platform-managed, access still restricted; `T` adds required `organizationId:ref(organizations)`; `C` adds T plus required `patientId:ref(patients)`, `patientRegistrationId:ref(patientRegistrations)`, and `Provenance`. Clinical child records also have optional `encounterId:ref(encounters)`; root appointments, visits and encounters do not inherit that back-reference. `P` means patient-controlled and adds `patientId`. `X` uses explicit `custody:{kind:E(PATIENT,ORGANIZATION,USER),patientId?:ref(patients),organizationId?:ref(organizations),userId?:ref(users)}` with exactly one custodian and a separate subject patient if applicable. USER custody supports a practitioner's private credential evidence before an organization owns it. A clinical record in C must reference a registration in its own organization. Historical records retain custody even after an affiliation ends.

`U(a,b)` = unique compound index; `Q(a,b)` = query index; `PU(predicate;a,b)` = partial unique index. Ascending order is default; `-field` is descending. Index keys include T's `organizationId` unless stated global. These are initial indexes to validate against measured queries; their exact operator definitions are expanded in the index document. All collections have `_id` uniqueness automatically.

No hard deletes for signed clinical data, posted finance, consent evidence or audit. Each collection's retention class is assigned in deployment policy; a database soft-delete plugin must not hide evidence or free regulated identifiers for reuse.

## Shared bounded values

| Value             | Fields and rules                                                                                                                                                                                                                                                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Name`            | `display:s`, `given?:s`, `middle?:s`, `family?:s`, `prefix?:s`, `native?:s`; support a single name without mandatory surname                                                                                                                                                                  |
| `Address`         | `id:id`, `use:E(HOME,WORK,MAILING,TEMPORARY)`, `line1:s`, `line2?:s`, `locality?:s`, `city:s`, `district?:s`, `stateCode:s`, `postalCode:s`, `countryCode:s`, `geo?:Point`, `period?:Period`; India postal codes are strings                                                                  |
| `Point`           | `type='Point'`, `coordinates:[longitude,latitude]` exactly two bounded numbers; geocode accuracy/source optional on parent                                                                                                                                                                    |
| `Contact`         | `kind:E(PHONE,EMAIL)`, `value:s`, `normalized:s`, `use:E(PERSONAL,WORK,EMERGENCY)`, `verifiedAt?:t`; verification does not prove patient identity                                                                                                                                             |
| `Period`          | `start:t`, `end?:t`; end later than start; half-open time intervals                                                                                                                                                                                                                           |
| `Code`            | `system:s`, `code:s`, `display:s`, `version?:s`; coding is preserved with display snapshot                                                                                                                                                                                                    |
| `Concept`         | `text:s`, `codings:[Code]5`; at least text or a coding; coded values required where contract specifies                                                                                                                                                                                        |
| `Quantity`        | `value:d`, `unit:s`, `system?:s`, `code?:s`; unit normalization is explicit                                                                                                                                                                                                                   |
| `Money`           | `minor:i`, `currency:s`, `exponent:i`; use exact operations; reject unsafe integer results; INR exponent 2                                                                                                                                                                                    |
| `Provenance`      | `source:E(PATIENT,CLINICIAN,DEVICE,IMPORT)`, `recordedAt:t`, `recordedBy:Actor`, `effectiveAt?:t`, `sourceDocumentId?:ref(documents)`, `sourceSystem?:s`, `externalId?:s`                                                                                                                     |
| `ResourceRef`     | `type:s` from a fixed collection allowlist, `id:id`; reference resolution enforces scope and type, never a user-controlled collection name                                                                                                                                                    |
| `ClinicalHead`    | `status:E(DRAFT,SIGNED,AMENDED,ENTERED_IN_ERROR)`, `currentRevisionId?:ref(clinicalRevisions)`, `signedAt?:t`, `signedBy?:ref(practitioners)`, `correctionReason?:s`; signed payload is not editable                                                                                          |
| `PolicySnapshot`  | `policyId:ref(policyVersions)`, `version:i`, `acceptedAt:t`, `acceptedBy:Actor`; the referenced version is immutable                                                                                                                                                                          |
| `PriceSnapshot`   | `priceId:ref(prices)`, `base:Money`, `discount:Money`, `tax:Money`, `total:Money`, `sellerOrganizationId:ref(organizations)`, `calculationVersion:s`; total arithmetic validated                                                                                                              |
| `ScheduleRule`    | `weekday:i(0..6)`, `localStart:s(HH:mm)`, `localEnd:s(HH:mm)`, `slotMinutes:i`, `stepMinutes:i`, `breaks:[local interval]10`; overnight rules explicitly split/flagged                                                                                                                        |
| `DoseInstruction` | `sequence:i`, `dose?:Quantity`, `route:Concept`, `timing:{frequency?:i,period?:d,periodUnit?:s,timesOfDay?:[s]12}`, `asNeeded:b`, `asNeededReason?:Concept`, `maxDose?:Quantity`, `duration?:Quantity`, `instructions:s`; at least structured dose or explicit governed free-text instruction |
| `FileObject`      | `provider:s`, `bucket:s`, `key:s`, `objectVersion:s`, `sha256:s`, `sizeBytes:i`, `mimeType:s`, `encryptionKeyRef?:s`; never a permanent public URL                                                                                                                                            |

Suggested safety caps: names 200 characters, email 254, ordinary labels 200, explanations 4,000, clinical sections 32,000, addresses 10 per profile, contacts 10. Larger legitimate clinical documents use separate records/files. Validate complete BSON size and clinical-specific limits before persistence. String enums below describe baseline product choices, not universal medical terminology.

Birth dates may use reduced precision (`YYYY` or `YYYY-MM`) only when the adjacent precision field declares it; ordinary operational date values remain `YYYY-MM-DD`. Do not invent an exact birthday. Money is nonnegative unless the field is explicitly a signed rounding/adjustment value; journal debit/credit sides remain nonnegative. Prescription signing caps one prescription at 100 items; larger orders are split into explicitly related prescriptions. A service offering's price/policy and duration/resource constraints become mandatory at activation; drafts may omit the price link while the first price version is created.

## Clinical records and prescribing

Each C collection below inherits clinical subject/custody/provenance. Fields described as content are frozen in a signed `clinicalRevisions` snapshot; workflow state can evolve only through an audited command. `allergies`, `conditions`, `medicationStatements`, and `medicalHistoryEntries` also have `currentRevisionId?:ref(clinicalRevisions)`. Audit path names alone are not sufficient to reconstruct prior clinical facts.

## Avoiding duplicate sources of truth

- Patient addresses, contacts and emergency contacts are bounded values; separate collections are only needed if independently queried effective-dated history becomes a requirement. Provider registration snapshots retain visit context.
- Doctor specialties are bounded references on the doctor and affiliation. `doctorSpecializations` is a logical join, not a required physical collection.
- `symptoms` and `diseases` are governed views of `clinicalConcepts`; `concernMappings` covers specialty routing and separately labeled condition associations.
- `prescriptionItems` stays separate because dispensing and administration need stable per-medication IDs. The signed prescription snapshot embeds its bounded item content to seal the whole document.
- Invoice lines stay separate for source-charge reconciliation; issue freezes the parent and lines together. A separate PDF is a rendering, not the accounting authority.
- `auditEvents` includes document-read/URL-issuance events; a second document-access collection is unnecessary initially.
- `appointmentEvents` includes reschedule and status history. A separate reschedule-request collection is needed only if a human approval workflow is introduced.
- Public profile and clinical summary caches are projections. In the first release, clinical summaries are policy-filtered queries; a dedicated summary collection is deferred until measurement justifies it.
