# Hospital and partner collection extensions

These collections use the types, base fields, custody rules, and index notation in [the core dictionary](04-data-model-core.md). Diagnostic orders, immunization history and referrals can be enabled for outpatient providers before a hospital rollout. Bed, nursing, stock and payer capabilities are delivered as complete operational modules, not partial generic CRUD screens.

The broad coverage follows the distinction between hospital registration, clinical services, laboratory, inpatient operations, stock and finance documented by [Bahmni](https://www.bahmni.org/feature-list/). The actual schemas below are proposed DocDuniya designs.

Cross-provider laboratory work requires explicit exchange. An ordering provider retains its order; a performing organization creates its own locally scoped work/results linked by integration identifiers. Do not let laboratory users update the ordering hospital's clinical rows directly. Validate custody and import provenance when results return. Report/result separation aligns with [FHIR DiagnosticReport](https://hl7.org/fhir/R4/diagnosticreport.html).

Standalone pharmacies cannot access all records because a patient has a platform account. They require a valid prescription exchange and authorized local workflow. Keep prescribing, reported use, dispensing and actual administration separate, consistent with the distinctions in [FHIR MedicationRequest](https://hl7.org/fhir/R4/medicationrequest.html).

An external prescription is retained as immutable source evidence and mapped to a locally scoped imported prescription with verified source identity/provenance before dispensing. Importing staff do not become the original prescriber, and an imported signature is not re-created as a local clinician signature. Cross-organization source links pass through the integration/sharing policy, not ordinary local reference writes.

## Specialist boundaries requiring a dedicated design

| Capability                                | Boundary to preserve before adding it                                                                                                                                            |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Blood bank                                | Donors, donations, components, infectious screening, compatibility/crossmatch, reservation, issue, transfusion and reactions; licensed blood-bank workflow required              |
| ICU and devices                           | Device identity, high-frequency waveform storage, alarm acknowledgement, calibration and bedside reliability; ordinary observations do not constitute a device monitoring system |
| Dialysis, oncology, obstetrics, fertility | Specialty protocols, sessions/cycles, longitudinal safety checks and dedicated records reviewed by specialists                                                                   |
| HR and payroll                            | Employee contracts, attendance, salary/tax processing; platform membership is access control, not payroll                                                                        |
| Biomedical maintenance                    | Equipment asset registry, calibration, preventive maintenance, failure and service tickets; separate from reservable resource availability                                       |
| Hospitality and logistics                 | Diet orders, meals, laundry, housekeeping, waste, ambulance journeys; integrate with operational tasks initially only where a complete workflow is specified                     |
| Advanced accounting                       | Statutory books, tax returns, procurement payables and fixed assets; export the verified subledger to an accounting system                                                       |

These boundaries make the common design extensible without claiming that a generic `metadata` field supplies every hospital specialty. The launch agreement must identify which of these are required before detailed schemas for that module are approved.
